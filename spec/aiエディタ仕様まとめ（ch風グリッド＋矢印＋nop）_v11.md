# AIエディタ仕様まとめ（CH風グリッド＋矢印＋NOP）（v11）

本書は、カルネージハート風のAIエディタ（グリッドにチップを配置し、矢印で遷移／壁でループ／NOPで道を作る）について、これまでの会話で合意した内容を整理した仕様メモです。

## 更新メモ（v11）
- 左パレット（チップパレット）の **カテゴリ構成／並び順／スターターセット（最初に表示する最小チップ群）** を追加。
- 左パレットのチップタイル表示（必須パラメータ未設定バッジ、Instant/Yield/Runningタグ、最近/お気に入り）を明記。
- 右パレットを **タブ構成（インスペクタ／概要・検証／テスト・デバッグ／ヘルプ）** として整理（MVPはインスペクタ＋概要）。
- **スマートデフォルトを確定**（例：`ExitExists` のデフォルト `R=6`）。R/%/秒のプリセットと入力制約（0.1s刻み等）を追記。
- 「同設定で複製→スタンプ化」「設定コピー/貼り付け」を追記。

## 1. コンセプト

- **グリッド上にチップを配置**してプログラムを構成する。
- **分岐は矢印**で表現し、チップごとに「次に進む方向」を設定する。
- プログラムカウンタ（PC）が進み、**壁（盤外／空セル）に当たったら START（STARTチップ位置）に戻って続行**する。
- **処理がない場所は NOP チップで埋めて「道」を作る**。
- **空セル（未配置）は壁扱い**とし、矢印の移動先が空セルでも壁と同様に START に戻る。

---

## 2. 用語

- **セル**：グリッドの1マス。
- **チップ**：セルに配置する命令。実行結果に応じて次のセルへ遷移する。
- **START（STARTチップ）**：開始セル。グリッド上に配置された **STARTチップのセル位置**。PCの初期位置であり、壁（盤外／空セル）に当たった時の戻り先。
- **PC（Program Counter）**：現在実行中（次に実行する）セル位置。
- **AI Tick**：AIの更新単位（一定間隔で実行されるAI処理の1回分）。  
  - 例：**1 Tick = 0.1秒**（この値はゲーム側の設計で調整可能）
  - ※描画フレーム（60fps等）とは別概念でもよい
- **Step**：AI Tick内でチップを1回実行すること。
- **MAX_STEPS**：AI Tick内に許可するStepの最大回数（無限ループ対策）。
- **感知範囲（Sense Radius）**：センサーが「存在/距離」を返せる最大距離。基本は遮蔽無視の距離。ゴーレムの基礎値（装備/遺物で増減）と、チップ側の任意制限（あれば）で決まる（後述）。
- **スナップショット（Snapshot / Perception）**：Tick開始時点の世界状態を切り出した読み取り専用データ。**同じTick内ではセンサー値は変化しない**（条件/センサーはスナップショットを参照）。
- **Memory（内部状態）**：AIがTickを跨いで保持する状態。カウンタ／フラグを含む。
- **カウンタ（Counter）**：0〜99の数値レジスタ（デフォルトA/B/C/D）。
- **フラグ（Flag）**：ON/OFFのビット（デフォルト5色）。
- **HazardTiles（危険タイル集合）**：スナップショットに含まれる「今この瞬間に危険なタイル」の集合。**罠／赤床・赤線（予兆）／発動中判定／持続床**をすべて統合して扱う。
- **Intent（目的地）**：MoveTo系ACTが黒板に書く「現在の目的地タイル」。EvadeHazardなどが参照して「避けたあと元の目的地に戻る」を実現する。
- **壁**：盤外、または空セル（未配置）。

## 3. グリッド仕様

- **盤面サイズ**：例）12×12（将来的に拡張してもよい）。
- **STARTチップ（開始位置）**：
  - 新規作成時は左上（旧A1相当）に **STARTチップを自動配置**（推奨）。
  - グリッド上に **必ず1つだけ** 存在する（複数／0個は不可）。
  - **PCの初期位置**は STARTチップのセル。
  - PCが **盤外／空セル（未配置）** に遷移しようとした場合は、PCを **STARTチップ位置** に戻す。
  - （推奨）**フロア遷移（次フロアへ移動して出現した瞬間）**でも、PCを **STARTチップ位置** にリセットする（新フロアでの初動が直感的になる）。
  - STARTチップが存在しない／複数ある場合は **実行不可（エラー表示）** とする。
- **空セルの扱い**：
  - 空セルは**壁扱い**。
  - 矢印の遷移先が空セルの場合も「壁に当たった」とみなす。

## 4. チップ仕様（最小分類）

### 4.0 START（開始）

- **開始位置を示す専用チップ**。**AI開始時（フロア開始/実行開始）** のPC初期位置であり、PCがリセットされる際の戻り先でもある。
- ※PCは **Tickを跨いで保持**される（毎Tick STARTへ戻るわけではない）。詳細は 6.1 / 6.3 / 6.4 を参照。
- **グリッド上に1つだけ**置ける（複数／0個は不可）。
- 実行時の挙動：
  - 処理内容は **NOP相当（即時・時間消費なし）**。
  - **単一遷移（緑の三角矢印）** を1本持つ（初期値：下方向を推奨）。
- PCリセット：
  - PCが盤外／空セルへ遷移しようとした場合、PCを **STARTチップ位置** に戻す（同Tick内で続行）。

### 4.1 NOP（道）
- 何もしない（時間も消費しない）。
- **通路を作るためのチップ**。
- 1本の「次方向（単一矢印）」を持つ。

### 4.2 条件チップ（分岐）
- **True / False の2値**を返す。
- **True矢印**と**False矢印**を別々に持つ（分岐種類は2択のみ）。
- 基本は即時（時間を消費しない）。

#### 4.2.1 共通パラメータ
- 多くの条件チップは以下のパラメータを持つ（チップ種により一部省略）：
  - **距離（Rタイル）**：敵/宝箱/出口/Hazard などの **世界センサー系条件チップでは必須**（例：`R=3`）。
  - **比較演算子**：`<, <=, ==, !=, >=, >`
  - **閾値（しきい値）**：数値（例：距離、秒、%）
  - **否定（Invert）**：結果を反転する（UIでは `!` マーク表示）
    - 例：`EnemyExists(R=3)` を否定すると「**3タイル以内に敵がいない**」になる

#### 4.2.2 追加する条件チップ（3点セット）
本プロジェクトでAIの「賢さ」を一段上げる最小セット。

##### A) Random（確率分岐）
- `Random(p%)`
  - `p`% の確率で True を返す
  - **同じTick内では同じチップは同じ結果**（リロール防止：Tick内キャッシュ）
  - 次Tickでは再抽選する

##### B) Time（経過時間）
- `TimeElapsed(kind, op, t_sec)`
  - `kind`：`Floor`（フロア開始から） / `Combat`（戦闘開始から） ※Combatは未実装でも可
  - `op`：比較演算子
  - `t_sec`：秒（例：`5.0`）
- 参照値はスナップショット `S(t)` の時間（Tick内で固定）

##### C) 自機内部状態（HP% / Energy%）
- `SelfHP(op, x_percent)`
  - 例：`SelfHP(<, 50)` → **HPが50%未満ならTrue**
- `SelfEnergy(op, x_percent)`
  - 例：`SelfEnergy(<=, 20)` → **Energyが20%以下ならTrue**
- 値はスナップショット `S(t)` の内部状態（Tick内で固定）

#### 4.2.3 AI内部状態（カウンタ／フラグ）の判定
- `CounterCmp(id, op, value)`
  - `id`：`A/B/C/D`（デフォルト4本）
  - `value`：0〜99
- `FlagIsOn(color)`
  - `color`：`Red/Green/Blue/Yellow/Purple`（デフォルト5色）
  - 否定（`!`）で「OFFか？」も表現できる

> 注：敵/宝箱/出口/Hazard等の「世界センサー条件」は 4.4 の定義に従う（`EnemyExists` / `HazardInRange` など）。


### 4.3 行動チップ（ACT）
- 攻撃、回避、移動（出口へ向かう等）、宝箱操作など。
- **時間を消費する**チップが中心。
- 実行結果として **Running（ブロッキング）** や **Yield（非ブロッキング）** を返し得る（後述）。

#### 4.3.1 MoveTo系（Yield：0.1秒ぶんだけ移動）
- `MoveToExit` / `MoveToTreasure` / `MoveToEnemy` など。
- **到達していない場合**：0.1秒ぶん移動して **Yield**（Tick終了、PCは次へ進む）
- **到達済みの場合**：**Success**（即時、同Tick内で次へ進める）
- **対象を検知できない場合**：**Failure**（即時）
- MoveTo系は毎回、黒板に `intent_target_pos`（目的地タイル）を書き込む（EvadeHazardが参照）。

> 重要（MVP）：MoveTo系は **Hazard（罠/赤床等）を自動回避しない**。  
> 「踏みたくない」挙動は、回路側に `HazardInRange` / `HazardOnSelf` と `EvadeHazard` を書いて作る。

- 出口（階段）は **踏んだら自動で次フロアへ遷移**（MVP）。  
  そのため `TakeStairs` のようなインタラクトACTはMVPでは不要。

#### 4.3.2 EvadeHazard（Yield：危険回避1手）
- 目的：Hazardタイルから退避／Hazardに近づかないように「1手」だけ動く。
- 候補：周囲 **8近傍**（斜め含む）1マス移動。
- 選択優先度（上ほど優先）：
  1. 移動先が **Hazardではない**
  2. 「最も近いHazardまでの距離」が **大きい**
  3. `intent_target_pos` がある場合、目的地に **近づく**
  4. `prev_pos`（直前位置）への戻りにはペナルティ（往復防止）
- 全候補がHazard等で安全地が無い場合は、上記スコアで「最もマシ」な1手を選ぶ。

#### 4.3.3 Wait（Running：思考停止）
- `Wait(t_sec)`
- 目的：指定時間だけ **思考（チップ実行）を止める**（タイミング調整用）。
- 挙動：
  - 残り待機時間 `wait_remaining` を内部に保持する。
  - `wait_remaining > 0` の間は **Running** を返す（Tick終了、PCはそのまま）
  - Tick終端のΔ=0.1秒シミュレーションで `wait_remaining -= Δ`
  - `wait_remaining <= 0` になったTickの次回実行で **Success** を返して矢印先へ進む
- 注意：Wait中は他の条件チェックも止まるため、長いWaitは反応が鈍くなる（仕様としての弱点）。


### 4.4 センサー／データ
- センサー値の取得や、フラグ・カウンタ等の状態更新。
- 多くは即時完了（Success/Failure）を想定。

#### 4.4.1 感知範囲（R）
- センサー系チップ（敵/宝箱/出口/罠 など）は、**感知範囲R内**の対象のみを「存在する」「距離が取れる」ものとして扱う。
- 感知範囲の決まり方（推奨）：
  - `R_base`：ゴーレム側の基礎感知範囲（装備/遺物などで増減）。未指定なら∞。
  - `R_chip`：チップ側で指定する距離（タイル）。**世界センサー系の条件チップでは必須**（MoveTo系ACTなどは任意で未指定なら∞）。
  - `R_effective = min(R_base, R_chip)`
- **遮蔽（壁）は無視**（大広間前提）。将来「遮蔽あり」を追加する場合は別フラグで切替可能。

#### 4.4.2 Exists系 / Distance系の扱い（例）
- `EnemyExists(R=3)`：`R_effective` 内（=3タイル以内など）に敵が1体でもいれば True。
- Exists系（存在判定）は結果に対して **否定（Invert / `!`）** を設定できる（4.2.1）。
  - 例：`EnemyExists(R=3)` を否定 → **3タイル以内に敵がいない**なら True（1体でもいれば False）
- `EnemyDist(op, x, R=6)`：`R_effective` 内の敵（ターゲット優先／なければ最寄り）の距離を `op x` で比較して True/False を返す。範囲内に敵がいなければ False。
- `TreasureExists(R=4)` / `ExitExists(R=6)` も同様（Rは必須）。
- `MoveToX` 系ACTは、基本「**検知できている対象**」に対してのみ移動先を持てる（検知できない場合はFailure即時）。※探索用に `Wander/Patrol` 等を入れるならここを拡張する。


#### 4.4.3 Hazard（統合危険：罠/赤床/発動中/持続床）
- Hazardは「踏みたくない危険」をすべて統合した概念。
  - **静的Hazard**：床罠（常に見える）
  - **動的Hazard（予兆）**：赤床/赤線（敵・技ごとに予兆時間が異なる）
  - **動的Hazard（発動中/持続）**：レーザー発射中、爆発判定、灼熱床など
- AI用には、Tick開始時スナップショットで `HazardTiles`（危険タイル集合）を生成し、**以後同Tick内は固定**とする。
- ※`HazardTiles` は「真の危険」ではなく、**自機が知覚できる危険**を入れる（例：敵ごとに予兆の見え方/表示時間差を入れるなら、ここで反映する）。
- 範囲攻撃（円/線/扇など）は、AI用にタイルへラスタライズして `HazardTiles` に含める。  
  MVPは安全寄りに「**範囲がタイルに少しでも重なればHazard**」とする。

##### Hazardセンサー（例）
- `HazardOnSelf`：自分のいるタイルが `HazardTiles` に含まれていれば True（Rなし）
- `HazardInRange(R=2)`：半径 `R_effective`（=min(R_base, R_chip)）以内にHazardが1つでもあれば True（Rは必須）

> 補足：分岐種類は True/False に限定する方針。多分岐は条件チップを連続させて表現する。

#### 4.4.4 AIレジスタ（カウンタ／フラグ：3点セット）
AIは世界スナップショットとは別に、**AI内部状態（Memory）**を持つ。  
カウンタ／フラグはこのMemoryに保存され、Tickを跨いで保持される。

##### カウンタ（Counter）
- 本数：`A/B/C/D`（デフォルト4本、将来拡張可）
- 値域：`0〜99`（整数）
- 初期値：0
- 端数処理：範囲外に出た場合は **クランプ**（`<0 → 0`, `>99 → 99`）

**操作チップ（即時：Success）**
- `CounterSet(id, value)`：指定値にセット
- `CounterAdd(id, delta)`：加算（負の値で減算）

**判定チップ（条件：True/False）**
- `CounterCmp(id, op, value)`（4.2.3参照）

##### フラグ（Flag）
- 本数：`Red/Green/Blue/Yellow/Purple`（デフォルト5色、将来拡張可）
- 値域：ON/OFF
- 初期値：OFF

**操作チップ（即時：Success）**
- `FlagOn(color)`
- `FlagOff(color)`

**判定チップ（条件：True/False）**
- `FlagIsOn(color)`（4.2.3参照、否定でOFF判定）

##### リセット規則（推奨）
- **フロア開始時（次フロアへ移動して出現した瞬間）**に、全カウンタ=0／全フラグ=OFFへリセット。
  - ※将来「ランを跨ぐ記憶」や「味方連携」を入れる場合は別途定義する。

## 5. チップの実行結果（共通インターフェース）

各チップは実行結果として以下のいずれかを返す。

- **Success**：処理が完了した（即時）。このTick内で次のチップへ進める。
- **Failure**：処理は完了したが失敗扱い（即時）。このTick内で次のチップへ進める。
- **Running（ブロッキング）**：処理が継続中（行動終了待ち）。  
  - **そのTickは即終了**し、PCは**そのチップ位置に留まる**  
  - 次Tickは**同じチップから再開**する  
  - 例：攻撃、回避、詠唱、硬直のあるアクション
- **Yield（非ブロッキング）**：そのTick分の行動は行うが、待ち続けない。  
  - **そのTickは即終了**し、PCは**矢印先へ進めた状態**になる  
  - 次Tickは**矢印先から再開**する  
  - 例：`MoveToExit` / `MoveToTreasure` のような「0.1秒ぶんだけ移動して次へ」

> まとめ：**Success/Failureは時間を消費しない**、**Running/Yieldは時間を消費する**（＝そのTickを終える）。

## 6. 実行モデル（確定版）

### 6.0 Tickライフサイクル（スナップショット方式：確定）
- Tick開始時に、世界状態から読み取り専用のスナップショット `S(t)` を作る（敵/宝箱/出口/罠/危険床、HP/Energy/CD、経過時間、`HazardTiles` など）。
- **同じTick内でセンサー値は変化しない**（条件/センサーは `S(t)` を参照）。
- AI実行（チップ実行）で、そのTickに行う「時間消費アクション（Running/Yield）」を最大1つ決定する。
- Tickの最後に、選ばれたアクションを **Δ=0.1秒ぶん** シミュレーションして世界状態を更新する（移動・被弾・罠発動など）。
- 次Tickでは更新後の世界から `S(t+Δ)` を作る。

> 例：敵が赤床を出した瞬間にAIが反応できるのは最速でも「次Tick」から（最大0.1秒遅れ）。予兆が0.8〜1.2秒級なら十分回避可能。

### 6.1 基本（Tick内は即時チップを進める）
- AIは **PC（現在位置）** を持つ。
- AI Tickごとに、PCから開始して最大 **MAX_STEPS** 回までチップを実行する。
- **Success/Failureのチップは同じTick内で連続実行してよい**（条件チェックを一気に通すイメージ）。
- **Running または Yield が返った瞬間に、そのTickは終了**する。  
  → 結果として「1 Tickで、時間を使う行動（ACT）は最大1回だけ」が基本挙動になる。

### 6.2 壁（盤外／空セル）に当たった場合
- 遷移先が **盤外** または **空セル** の場合：
  - PCを **START（STARTチップ位置）に戻す**。
  - そのAI Tick内で **続行**する（残りStepがある限り）。

### 6.3 Running（ブロッキング）の扱い（確定）
- チップ実行結果が **Running** になった瞬間：
  - **そのAI Tickの実行は即終了**。
  - PCは**そのチップ位置に留まる**。
  - 次のAI Tickは **同じチップから再開**する。

> ユーザー理解：Runningは「行動終了待ち」。その認識でOK。

### 6.4 Yield（非ブロッキング）の扱い（追加確定）
- チップ実行結果が **Yield** になった瞬間：
  - **そのAI Tickの実行は即終了**。
  - PCは **矢印先へ進めた状態**（次に実行するチップが更新済み）になる。
  - 次のAI Tickは **更新後PCから再開**する。

> 例：`MoveToTreasure(Yield)` の次が `Heal(Running)` の場合、  
> 「0.1秒だけ宝箱へ移動」→（次Tick）「その場で回復行動（完了まで待つ）」となる。

### 6.5 MAX_STEPS（無限ループ対策）
- AI Tick内でチップ実行を **MAX_STEPS** 回までに制限する。
- MAX_STEPSに到達した場合：
  - そのAI Tickを終了。
  - 次のAI Tickは **その時点のPCから継続**する。
- これは安全装置であり、頻発する場合は回路が「時間を使う行動に到達できていない」可能性が高い。


### 6.6 優先度（if / elif 相当）を配線で表現するコツ
- **Yieldはその場でTickを終える**ため、配線次第で「次Tickにどこから戻るか」が挙動を決める。
- `elif` 的に「宝箱があるなら出口チェックをしない」を作りたい場合：
  - `MoveToTreasure(Yield)` の**矢印先で「STARTへ戻る」動線を作る**  
    - 例1：矢印を **盤外／空セル（壁）方向**へ向けて、6.2 のルールで **PCリセット（STARTへ）** を起こす
    - 例2：NOPを並べて、物理的に **STARTチップへ戻る経路** を作る
  → 次TickもSTART（STARTチップ）から評価し、宝箱がある限り宝箱が優先される（出口チェックへ行かない）。

---

### 6.7 AI内部状態（Memory）とTick内キャッシュ（追加確定）
- AIは `S(t)`（世界スナップショット）とは別に、永続の内部状態 `M` を持つ。
  - `M`：カウンタ（A/B/C/D）とフラグ（5色）を保持（4.4.4参照）
  - `M` は **Tickを跨いで保持**される（推奨：フロア開始でリセット）
- 1Tick内でのみ有効なキャッシュ `C_tick` を持つ（推奨）：
  - `C_tick.random[cell_id]`：`Random(p%)` の結果（Tick内リロール防止）
- 「世界センサー（敵位置/HP/Energy/時間など）」は `S(t)` を参照し **Tick内で固定**。
- 「カウンタ/フラグ」は `M` を参照し、**同じTick内でも書き換えが即反映**される。



### 6.8 時間を消費する行動に到達できなかった場合（Idle）
- そのTick内で **Running/Yield が1度も発生しない**まま、MAX_STEPS到達などでTickが終了するケースがあり得る。
- この場合でも **ゲーム時間は Δ=0.1s 進む**（敵行動・床効果・クールダウン等は進行）。  
  自機はそのTickは **Idle（その場待機）** として扱う（移動/攻撃なし）。
- PCは **MAX_STEPS到達時点の位置**を保持する（6.5）。  
  ※「毎Tick STARTから評価したい」場合は、回路側で **壁ヒット戻り** や **NOP経路** を作ってSTARTへ戻す。

## 7. 代表例（「回避→攻撃」）

回避チップの直後に攻撃チップが並んでいる場合：

1. PCが回避ACTに到達 → 回避開始、**Running** → そのAI Tick終了（PCは回避セル）
2. 次AI Tick：回避中なら引き続き **Running**（待ち）
3. 回避完了Tick：回避ACTが **Success** → 矢印で攻撃ACTへ進む（同Tick内で到達できれば攻撃判定へ）
4. 攻撃ACTを実行（必要ならRunningで継続）

このため、**回避行動が終わった後に攻撃行動へ移る**。

## 10. 実行アルゴリズム（擬似コード）

```text
# 永続（フロア開始でリセット推奨）
M = {
  counters: {A:0, B:0, C:0, D:0},
  flags:    {Red:false, Green:false, Blue:false, Yellow:false, Purple:false},
}

# フロア開始時（または編集確定時）に一度だけ解決
START_POS = find_start_chip_pos()   # STARTチップのセル座標
assert unique(START_POS)            # 0個／複数なら実行不可（エラー表示）

# 初期PC
PC = START_POS

AI_Tick():
  S = build_snapshot()   # Tick開始時スナップショット（HazardTiles, HP/Energy, 経過時間など）
  C_tick = {}            # Tick内キャッシュ（Random結果など）
  steps = 0

  while steps < MAX_STEPS:
    chip = cell_at(PC)

    # 壁（盤外/空セル）ならSTARTへ戻す
    if chip is None:
      PC = START_POS
      steps += 1
      continue

    result = chip.execute(S, M, C_tick)

    if result == Running:
      # Running（ブロッキング）でTick終了（PCはそのまま）
      break

    if result == Yield:
      # Yield（非ブロッキング）でTick終了（PCは矢印先へ進めておく）
      PC = chip.next_pc(result)  # 条件ならTrue/False矢印、それ以外は単一矢印
      if out_of_bounds(PC) or cell_at(PC) is None:
        PC = START_POS
      break

    # Success/Failure（即時）なら矢印で次へ（同Tickで続行）
    PC = chip.next_pc(result)  # 条件ならTrue/False矢印、それ以外は単一矢印

    # 次が盤外/空セルならSTARTへ戻して続行
    if out_of_bounds(PC) or cell_at(PC) is None:
      PC = START_POS

    steps += 1
```
